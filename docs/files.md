# Файлы и медиаданные

> Часть [технической документации](README.md). Передача файлов без интернета — [bluetooth.md](bluetooth.md).

## 1. Схема шифрования

1. Для каждого файла генерируются ключ (256 бит) и nonce (96 бит). Файл шифруется ChaCha20-Poly1305.
2. Идентификатор содержимого (CID) — SHA-256 шифротекста в hex. Ретранслятор отклоняет загрузку `POST /v1/blob/:cid`, если хеш тела не совпадает с CID.
3. Ключ, nonce, имя, размер и тип MIME передаются получателю сообщением E2EE. С 1.1.0-1 там же может лежать подпись к фото, видео или файлу — поле `cap` (до 4096 символов). Старые приложения поле не знают: подпись они не покажут, но сам файл откроют.
4. Получатель загружает шифротекст, сверяет хеш и расшифровывает файл.

Ретранслятор видит только размер шифротекста и время загрузки.

## 2. Хранение на ретрансляторе

Шифротексты хранятся на диске (`aqua-blobs/`, переменная `AQUA_BLOB_DIR`) как кэш доставки:

| Класс | Срок хранения | Предел размера |
|---|---|---|
| Обычные вложения | `AQUA_BLOB_TTL_HOURS`, по умолчанию 72 ч от последней загрузки; очистка — ежечасно | 210 МиБ на сервере, 200 МиБ в клиенте |
| Фото и баннеры групп (`?keep=1`) | 90 суток с последнего скачивания (скользящий срок) | 4 МиБ |

Получатель хранит расшифрованный файл в локальном кэше, поэтому истечение срока на сервере не делает полученное вложение недоступным. При федерации вложение, отсутствующее на узле, запрашивается у соседей и проверяется по CID.

## 3. Предварительная обработка

| Режим отправки | Обработка |
|---|---|
| «Фото или видео» со сжатием | Видео перекодируется на устройстве в H.264 720p (`ffmpeg`); изображения уменьшаются до 2560 px по большей стороне |
| «Файлом» | Оригинал без изменений |
| Голосовое сообщение, видеокружок | Запись первым поддерживаемым форматом: WebM (Opus; VP9 или VP8), затем OGG или MP4 |

Трек профиля не в MP3 или OGG перекодируется в Opus при загрузке. Аудио и видео, которые WebView не умеет воспроизводить, перекодируются `ffmpeg` на лету и отдаются локальным сервером воспроизведения (`media_server.rs`, только `127.0.0.1`).

## 4. Воспроизведение

Один проигрыватель для видео, аудио и голосовых: перемотка с буферизованным диапазоном, скорость, громкость колесом, повтор, режим кинотеатра, полный экран. Одновременно играет один проигрыватель. Музыка из статьи или чата продолжает играть при переходе в другие чаты.

## 5. Зависимости Linux

Воспроизведение в WebKitGTK выполняется через GStreamer:

| Пакет | Назначение |
|---|---|
| `gst-plugins-good` | Обязателен: без него WebKitGTK зависает при первом воспроизведении. Клиент проверяет его при запуске |
| `gst-libav` | Декодирование H.264 и AAC |
| `ffmpeg` | Обложки видео, сжатие и перекодирование |

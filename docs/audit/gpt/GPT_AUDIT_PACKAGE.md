## Обязательные вопросы

### Вход (AQUA-SEC-001)
- Нельзя ли получить токен чужого аккаунта другим путём?
  - Другие точки выдачи токенов: боты, Telegram-вход, `/v1/users/login`.
  - Ручки, которые принимают `identity` без proof.
  - Пути через federation (`fed_apply_user`, `h_deliver`).
- Корректна ли конструкция `dh_proof`?
  - Доменное разделение.
  - Привязка к nonce, `dh_pub` и `sign_pub`.
  - Проверка на нулевой секрет.
  - Время сравнения.
  - Повтор proof.
  - Гонка двух verify с одним nonce.
- TOFU-привязка `identity_signs`: можно ли зафиксировать чужой Ed25519 до первого входа владельца? Что происходит при законной смене ключа подписи (перенос аккаунта, восстановление из бэкапа)?

### Аккаунты и OTP (AQUA-SEC-002, 005)
- Не сломан ли законный сценарий «пропуск → вход на другом сервере сети»?
- Есть ли ещё места, где `identity_dh` аккаунта перезаписывается без доказательства?
- Можно ли обойти лимит попыток:
  - через повторный запрос кода;
  - через другой регистр почты;
  - через пробелы;
  - через параллельные запросы?
- Нет ли утечки кода через панель, логи (`tracing::warn!(%code)` в `send_email_code` и `deliver_code`) или `recent`?

### Конфигурация (AQUA-SEC-003, 004, 006)
- Есть ли пути, где dev-коды включаются неявно?
- Правильно ли `link_base` разбирает `Host` (IPv6, порт, юникод)?
- Не ломает ли `panic!` при недоступной БД встроенный сервер в `aqua-server-app`?

### CeZeOs (CZ-SEC-001)
- Нельзя ли получить demo-сессию через reverse proxy на том же хосте при `CEZEOS_ALLOW_DEMO=1`?
- Нет ли других путей создать сессию без входа?

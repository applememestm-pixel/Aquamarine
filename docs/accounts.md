# Учётные записи, вход и устройства

> Часть [технической документации](README.md). Методы — [api.md](api.md), разделы 2, 6, 7.

## 1. Аутентификация устройства

1. `POST /v1/auth/challenge` — ретранслятор выдаёт nonce (24 байта, срок действия 60 с).
2. `POST /v1/auth/verify` — клиент возвращает подпись Ed25519 над nonce.
3. Ретранслятор выдаёт токен `dh_pub ‖ expires_at ‖ HMAC-SHA256(server_key, …)` сроком 1 ч. Токен проверяется без хранения состояния.

## 2. Регистрация и пароль

Имя пользователя (`@имя`: 3–32 символа `a–z0–9_.`) регистрируется после подтверждения адреса электронной почты. Код действует 10 минут, регистрационный тикет — 30 минут. Если адрес уже зарегистрирован, ретранслятор отвечает сразу (`409`), не отправляя код; при входе с неизвестным адресом — `404`.

Пароль на ретранслятор не передаётся. Клиент передаёт производный секрет:

```
auth_secret = "aqv2$" ‖ hex(Argon2id(password,
                                     salt = SHA-256("aquamarine/auth/v1|" ‖ lower(email))[0..16],
                                     m = 19 МиБ, t = 2, p = 1))
```

Ретранслятор хранит PBKDF2-HMAC-SHA256(auth_secret; 120 000 итераций; случайная соль 16 байт).

- Учётные записи, созданные до введения `auth_secret`, проходят вход по прежней схеме и автоматически переводятся на новую.
- Без настроенного SMTP ретранслятор работает в режиме разработки: коды выводятся в консоль и в панель администратора.

## 3. Ключ восстановления и сброс пароля

При регистрации клиент показывает **ключ восстановления** — 24 слова BIP-39 (256 бит). Он открывает резервную копию ([backups.md](backups.md)) и позволяет сбросить забытый пароль. Ключ можно создать позже: «Настройки → Резервная копия».

Ретранслятор хранит только хеш проверочного значения:

```
check = HKDF-SHA256(энтропия ключа, info = "aquamarine account recovery v1")
```

Метка отличается от метки ключа копии, поэтому `check` не открывает копию.

**Сброс пароля** («Забыли пароль?» в окне входа):

1. подтверждение адреса кодом из письма (`purpose: "reset"`);
2. ввод 24 слов (если у учётной записи есть ключ восстановления);
3. новый пароль (не короче 8 символов): `POST /v1/users/reset {ticket, recovery, password}`. Затем клиент входит с новым паролем как обычно; резервная копия открывается ключом восстановления.

Учётную запись без ключа восстановления можно сбросить только по почте; резервная копия в этом случае не открывается, и устройство начинает с чистой историей.

## 4. Несколько устройств

Учётная запись работает одновременно на нескольких устройствах (до 11: основное и 10 дополнительных). У каждого устройства собственный ключ идентичности, собственные предварительные ключи и собственные сеансы; закрытые ключи между устройствами не передаются.

| Элемент | Устройство |
|---|---|
| Добавление | Вход на новом устройстве по подтверждённому адресу и паролю (`POST /v1/users/login`): ключ устройства добавляется к учётной записи |
| Адрес на ретрансляторе | Основное устройство — `имя`, дополнительное — `имя~<id>`, где `id` — первые 6 байт ключа DH в hex |
| Список устройств | `GET /v1/devices/:имя` (публичный); `GET /v1/me/devices`; `POST`/`DELETE /v1/me/devices/:id` — переименование и выход |
| Отправка | Сообщение шифруется для каждого устройства собеседника и каждого своего (`[sync:v1]`) |
| Отключение | С любого другого устройства. Отключение основного делает основным устройство, с которого выполнено действие |
| История | Хранится на ретрансляторе зашифрованной ключом устройств учётной записи (с 1.1.0-6): см. ниже |
| Передача чата | Открытый чат и черновик предлагаются на другом устройстве ([delivery.md](delivery.md#5-передача-чата-между-своими-устройствами)) |
| Совместимость | Старые клиенты видят только основное устройство собеседника; старые ретрансляторы отвечают 404 на `/v1/devices`, и клиент отправляет по имени |

### 4.1. Несколько учётных записей на одном устройстве

На одном устройстве можно держать несколько учётных записей и переключаться между ними: на главном экране телефона — удержание своей аватарки слева вверху (нажатие открывает профиль). В списке — все учётные записи устройства и «Добавить аккаунт».

| Элемент | Устройство |
|---|---|
| Данные | У каждой учётной записи свой каталог данных: первая — сам каталог приложения, остальные — `accounts/<a1, a2, …>/` в нём ([storage.md](storage.md#1-расположение)). Хранилище, история, медиа и ключи не смешиваются |
| Выбор | `accounts.json` в каталоге приложения называет текущую; каталог выбирается при запуске, поэтому переключение перезапускает приложение (`accounts.rs`, на Android — `AquaRelayPlugin.relaunch`) |
| Настройки интерфейса | Закрепления, папки, приватность, черновики и прочее из localStorage сохраняются в `webstore.json` уходящей учётной записи и восстанавливаются у открываемой; оформление, язык и сочетания клавиш общие для устройства (`ui/src/lib/accounts.ts`) |
| Добавление | Создаётся пустой каталог, приложение открывается в нём с окном входа. Незавершённый вход можно удалить из списка; учётную запись с выполненным входом сначала покидают через «Выйти» |
| Сервер на устройстве | Встроенный ретранслятор общий для всех учётных записей устройства (`relay/` в каталоге приложения) |

### История на всех устройствах

Сервер переписку прочитать не может (сквозное шифрование), но с 1.1.0-6 он её **хранит** — зашифрованной ключом, который есть только у устройств учётной записи (`history_sync.rs`). Поэтому чаты одинаковы на всех устройствах, а новое получает всю историю сразу после входа.

| Что | Как |
|---|---|
| Ключ истории | 32 случайных байта. Их создаёт первое устройство учётной записи, ретранслятор хранит только идентификатор ключа (`kid`, первая запись выигрывает, остальным — 409). Новое устройство берёт ключ из восстановленной резервной копии или просит его у своих устройств по E2EE (`[hkeyreq:v1]` → `[hkey:v1]`); принимается только ключ с тем же `kid` |
| Записи | Каждый чат — страницы по 200 сообщений и карточка (имя, вид, «надгробия» удалённого); группы — одна запись. JSON → DEFLATE → ChaCha20-Poly1305 этим ключом, связанные данные — имя записи. Имя записи — хеш с ключом: ретранслятор не знает, с кем чаты |
| Сохранение | Через ~2 с после изменения устройство отправляет изменённые записи (`PUT /v1/me/hist/:k`) и толкает свои устройства `[hpoke:v1]` по E2EE |
| Получение | Сразу после входа, по толчку и раз в минуту на всякий случай: «всё с номера N» (`GET /v1/me/hist?since=N`) |
| Слияние | Недостающие сообщения встают на своё место, ничего не удваивается. Сравнение — автор, время до минуты, текст (у правленого — первый вариант) или CID файла |
| Удаление | Удалённый чат или сообщение оставляет «надгробие» — 8 байт хеша. Другие устройства удаляют то же и не возвращают обратно |
| Федерация | Записи копируются между ретрансляторами сети, как резервные копии: устройство может подключиться к любому |

Управляющие сообщения `[hkeyreq:v1]`, `[hkey:v1]` и `[hpoke:v1]` принимаются только от своей учётной записи. Ключи идентичности и сеансы между устройствами не передаются. Ретранслятор держит не больше 1 ГБ истории на учётную запись и не больше 8 МБ на одну запись.

## 5. Защита на устройстве

### 5.1. Пароль приложения

Необязательный пароль приложения запрашивается при запуске и после бездействия (1, 5, 15 или 60 минут; можно выключить). `Ctrl+L` блокирует приложение сразу. Хранится как PBKDF2-SHA256 (150 000 итераций, соль 16 байт) только на этом устройстве.

Экран входа — карточка профиля: аватар, имя, поле пароля и кнопка «Войти»; ниже две кнопки:

- **«Забыл пароль»** — код на адрес учётной записи; после ввода кода пароль приложения снимается, новый задаётся в настройках;
- **«Выйти из профиля»** — выход с устройства; вход снова — по почте и паролю, чаты возвращаются из резервной копии.

После входа в учётную запись приложение предлагает задать пароль; предложение можно пропустить.

### 5.2. Пароли чатов

Отдельный чат можно закрыть своим паролем. В списке у такого чата размыто имя и скрыт предпросмотр; при открытии запрашивается пароль. Через 5 минут после ухода из чата он снова закрывается. Пока чат закрыт, отметки о прочтении не отправляются, уведомления приходят без текста. Собеседник ничего не видит.

Пароли хранятся как PBKDF2-SHA256 (200 000 итераций, своя соль у каждого чата) в настройках интерфейса; настройки входят в зашифрованную резервную копию, поэтому замки переходят на другие устройства учётной записи.

Пароль приложения и пароли чатов защищают интерфейс от постороннего за компьютером, а не файлы на диске ([storage.md](storage.md)).

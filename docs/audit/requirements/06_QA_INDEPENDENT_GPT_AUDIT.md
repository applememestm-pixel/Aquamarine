# QUALITY ASSURANCE & INDEPENDENT GPT AUDIT

## 1. Цель

Обеспечить проверяемое качество CeZeOs и Aquamarine.

Claude выполняет разработку и первичное тестирование.

ChatGPT GPT-6.2 проводит независимую проверку исходного кода и результатов изменений.

Нельзя считать собственный отчёт Claude независимым подтверждением правильности его работы.

## 2. Инвентаризация тестов

* Unit tests.

* Android tests.

Установить реальные команды запуска и фактическое покрытие.

## 10. Независимый GPT-аудит

Подготовить для GPT-6.2:

* Исходный код.
* Изменённые файлы.
* Git diff.
* Commit SHA.
* Исходный список проблем.
* Новые зависимости.
* Миграции.
* Логи.
* Результаты тестов.
* Benchmark results.
* Архитектурные решения.

GPT должен самостоятельно проверить:

* Корректность исправлений.
* Security.
* API.
* Database.
* Federation.
* E2EE.
* UI.
* Performance.
* Media.
* Frame processing.
* Android.
* Regression risks.

Не ограничивать GPT рамками выводов Claude.

## 11. Работа с замечаниями GPT

Каждое замечание получает статус:

* CONFIRMED.
* REJECTED.
* NEEDS INVESTIGATION.
* ALREADY FIXED.
* NOT REPRODUCIBLE.

Для подтверждённых замечаний:

1. Определить причину.
2. Найти конкретный участок кода.
3. Исправить.
4. Добавить тест.
5. Повторить тестирование.
6. Обновить diff.
7. Передать на повторную проверку.

Для отклонённых замечаний приложить техническое обоснование.

## 12. Регрессионный контроль

После каждого изменения проверять затронутые компоненты.

Перед релизом выполнять полный набор проверок.

Нельзя удалять тесты ради прохождения CI.

Нельзя отключать проверки безопасности ради успешной сборки.

## 14. Release Gate

До публичного релиза необходимо:

* Закрыть все подтверждённые P0.
* Закрыть согласованные P1.
* Проверить миграции.
* Проверить сохранность данных.
* Пройти регрессионные тесты.
* Проверить критические пользовательские сценарии.
* Проверить уведомления.
* Проверить федерацию.
* Проверить E2EE.
* Проверить медиа.
* Провести независимый аудит.

Не объявлять релиз готовым, если важные проверки не проводились.

Непроверенные области перечислять отдельно.

## 15. Итог

GPT должен выступать полноценным независимым техническим рецензентом.

Цель не в том, чтобы подтвердить работу Claude, а в том, чтобы обнаружить ошибки, которые Claude мог пропустить.

Окончательный результат — проверенная версия проектов с документированными изменениями и честным перечнем остаточных рисков.

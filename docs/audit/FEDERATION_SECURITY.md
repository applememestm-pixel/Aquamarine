# FEDERATION_SECURITY — модель доверия федерации Aquamarine

Состояние на 1.21.0-23 (PR #81, после раунда 2 независимого аудита).

## Кто есть кто
- **Общий секрет сети** (`secret`): HMAC над каждым запросом (`x-aqua-fed`). Исторический механизм. Сейчас нужен только для того, чтобы представиться (hello/ping) и работать со старыми серверами.
- **Ключ узла** (Ed25519):
  - свой у каждого сервера, хранится в `aqua-fed-node.key` в папке данных (права 0600);
  - в `aqua-federation.json` не записывается;
  - id узла = первые 16 байт SHA-256 открытого ключа.
- **Закрепление** (`pins`): url → id → открытый ключ пира, полученный из подписанного hello.
- **Подпись v2** (`x-aqua-fed2`): Ed25519 над методом, путём с query, временем, nonce, id отправителя, id получателя и SHA-256 тела. Каждая подпись принимается один раз (±5 мин).

## Режимы
| Режим | Когда | Что принимается |
|---|---|---|
| Переходный | Хотя бы у одного пира нет ключа (старый сервер) | v2 от закреплённых; HMAC от остальных — как раньше |
| Строгий | Закреплены ключи всех пиров | Только v2. HMAC — лишь для hello/ping/реестра имён. В список пиров попадают только закреплённые узлы |

## Допуск нового узла (решение владельца: по приглашению)
1. Админ берёт приглашение в панели. В `aquafed:` теперь есть одноразовый токен `t`: хранится хешем, действует 7 дней.
2. Новый узел вступает с приглашением и передаёт `t` в hello пригласившему.
3. Пригласивший закрепляет его ключ и отвечает подписью-поручительством `vouch` («я допустил id по url»).
4. Новый узел показывает `vouch` остальным, и они допускают его без отдельного токена.
5. Узел без токена и без поручительства в строгом режиме попадает в «Ожидают допуска». Читать он ничего не может; админ допускает его вручную (`POST /v1/admin/fed/admit`, кнопка «Допустить сервер»).

## Ротация ключа
- Кнопка «Новый ключ узла» (`/v1/admin/fed/rotate`): старый ключ подписывает новый, и hello с этой подписью переносит закрепление у всех пиров.
- Другой ключ для закреплённого адреса **без** подписи старым ключом не принимается: это подмена.

## Отзыв и компрометация
- `/v1/admin/fed/revoke {id}` убирает закрепление и адрес; id больше не принимается ни в подписях, ни в hello.
- Новый ключ того же сервера после отзыва в строгом режиме ждёт допуска.
- **Утёкший ключ (REV2-001).** Тестовый ключ узла был закоммичен в ветку PR. Он внесён в `LEAKED_NODE_IDS` и не принимается нигде. Сервер, у которого в файле окажется этот ключ, при старте создаёт новый. В истории ветки файл остаётся (без force-push), но ключ бесполезен.
- Если украден ключ узла:
  1. Отозвать id на всех серверах.
  2. Создать новый ключ.
  3. Допустить сервер заново по приглашению.
- Если украден общий секрет: сменить его на всех серверах. В строгом режиме секрет даёт только право представиться (узел попадает в «Ожидают»).

## Полномочия над аккаунтами
- Изменения аккаунтов приходят только при синхронизации от закреплённых и не отозванных пиров: опрашиваются только пиры из списка, а в строгом режиме это только допущенные узлы.
- Тест `admission_impersonation_and_rejoining` проверяет, что сервер с одним секретом не меняет аккаунт жертвы.

## Оставшиеся риски (честно)
| Риск | Почему остаётся | Что нужно |
|---|---|---|
| Допущенный злонамеренный узел может изменить любой аккаунт сети | Модель «одна сеть»: любой сервер сети может войти за пользователя и изменить его | Изменения безопасности (ключ, пароль, устройства), подписанные устройством аккаунта; дорожная карта P1 |
| Ответы на синхронизацию не подписаны | Целостность ответа сейчас держится на HTTPS между серверами | Подпись ответа ключом узла с привязкой к nonce запроса (`x-aqua-fed2-resp`) |
| Переходный режим уязвим, как раньше | Старые серверы без ключей | Обновить все серверы сети; строгий режим включается сам |
| Токен приглашения действует 7 дней | Удобство | Отзыв токена в панели — не сделан |
| Курсоры в памяти, нет монотонных номеров событий и tombstone удалений | — | Seq за флагом caps |

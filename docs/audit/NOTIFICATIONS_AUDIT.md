## Цепочка сообщения (Android)

1. `notify.ts` → `bg_sync_set` → `AquaRelayPlugin.syncStart` → `AquaSyncService` (foreground, `remoteMessaging`) держит процесс.
2. Сообщение принимает Rust; `commands.rs` вызывает `bgnotify::incoming`, если приложение не на экране.
3. Настройки показа (кому, что в тексте, замок) передаёт интерфейс: `notify_prefs`.

## Осталось

- Без открытия приложения после перезагрузки соединения нет: ядро запускается вместе с окном. Нужен либо запуск ядра из службы, либо push-шлюз (решение владельца).
- Приложение, снятое из «недавних» или усыплённое производителем телефона, уведомлений не получает; push-шлюза нет.
- Входящий звонок не показывается поверх экрана блокировки и не имеет кнопок «Ответить / Отклонить» (`ConnectionService` / full-screen intent не сделаны).
- iOS: фоновых уведомлений нет (нужен APNs).
- Звонок в фоне зависит от того, как WebView конкретного телефона ведёт себя на паузе.

## Пробуждение через push (ветка `claude/push-transport`, сервер; 27.11)

Сделано и проверено тестами (`push.rs`, `tests/push.rs`; каждый новый падал до исправления):
- Наружу уходит только `{"aq":"wake"}` — без текста, отправителя, чата и id.
- Адрес UnifiedPush проверяется в самом подключении (свой DNS-резолвер клиента): имя, которое при проверке отвечало «публичный», а при подключении — `127.0.0.1` (DNS rebinding), больше не проходит. Отклоняются и спецдиапазоны IPv4 (0/8, 192.0.0/24, 198.18/15, 240/4, multicast) и IPv6, несущие IPv4 (mapped, compatible, NAT64, 6to4), Teredo, site-local, документация, discard. Перенаправления не выполняются.
- Пробуждение, отложенное ограничением «раз в 20 с», раньше терялось — теперь отправляется по окончании ограничения (одно, не на каждое сообщение).
- Запись устройства, которое больше не принадлежит аккаунту (вышло, заменено), удаляется, а не будится; при выходе устройства — сразу. Устройство регистрирует только себя (ключ входа), `DELETE /v1/me/push` — отказ.
- Шлюзу передаётся ключ этого сервера (`AQUA_PUSH_GATEWAY_KEY`, `Authorization: Bearer`).
- Предпросмотр уведомлений по умолчанию — «Новое сообщение» (без отправителя и текста); полный текст — по выбору в настройках.

Android, UnifiedPush (без Google), 27.11:
- `AquaPush` / `AquaPushReceiver` (`android/AquaRelay.kt`) — протокол UnifiedPush AND_3 напрямую, без библиотеки: регистрация у установленного дистрибьютора (ntfy, NextPush…), адрес от него — только с нашим случайным токеном (чужое приложение не подставит адрес), https и не длиннее 2048. Выключение — отписка и новый токен в следующий раз.
- Ядро отдаёт адрес серверу после каждого подключения и при включении (`push.rs`, `POST /v1/me/push`; старый сервер без push — ничего).
- Сигнал «проснись» → уведомление только «Новое сообщение» (если приложение не на экране); если включено «Оставаться на связи» — попытка поднять службу подключения. Ядро Rust живёт в процессе окна: при убитом процессе сигнал не запускает ядро, сообщения придут при открытии приложения (по уведомлению).
- Настройки → Уведомления → «Пробуждение через UnifiedPush» (только Android).

Не сделано / не проверено:
- **На телефоне не проверено** (CI собирает APK): регистрация у ntfy, получение адреса, уведомление при убитом процессе, отписка.
- Шлюз FCM и сборка Android с ним не написаны; проверка ключа сервера, привязка токена к серверу и устройству и его отзыв — на стороне шлюза, его нет.
- Чужой токен шлюза, зарегистрированный другим аккаунтом, будит чужое устройство (спам пробуждений): закрывается на шлюзе привязкой токена.
- Время и частота пробуждений видны дистрибьютору / шлюзу и провайдеру за ним (метаданные), содержимое — нет.
- Через исходящий прокси сервера адрес разрешает прокси — проверка резолвера к нему не относится.
- Пробуждение ядра Rust при убитом процессе Android — не проверено (клиентской части нет).

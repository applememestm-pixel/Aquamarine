# HTTP API ретранслятора

> Часть [технической документации](README.md). Описание соответствует `aqua-server` 1.1.0-4 и версии протокола `v1`.

Ретранслятор (`aqua-server`) предоставляет HTTP API и канал WebSocket. Клиент Aquamarine работает только через них, поэтому API позволяет написать совместимый клиент, бота или инструмент администрирования.

Ретранслятор не получает открытого содержимого сообщений. Через API проходят зашифрованные конверты, шифротексты файлов и копий, открытые ключи и метаданные. Исключение — переписка с ботами (раздел 12).

## 1. Общие сведения

### 1.1. Адрес и версия

Базовый адрес — адрес ретранслятора, например `https://relay.example` или `http://192.168.1.10:7777`. Все пути, кроме панели администратора и слоя Telegram, начинаются с `/v1/`. Несовместимые изменения выпускаются под новым префиксом; поля, добавляемые в ответы, клиенты обязаны игнорировать.

Ретранслятор не реализует TLS сам. Для `https://` и `wss://` перед ним ставится обратный прокси (Caddy, nginx) — см. [deployment.md](deployment.md).

### 1.2. Форматы

| Что | Формат |
|---|---|
| Тела запросов и ответов | JSON, UTF-8, `Content-Type: application/json` |
| Вложения, резервные копии, медиа профиля | Двоичные данные (`application/octet-stream` или тип MIME файла) |
| Двоичные поля внутри JSON (открытые ключи, подписи, полезная нагрузка конвертов) | Массив чисел 0–255 (сериализация `serde_bytes` в JSON) |
| Nonce и подпись в аутентификации | Base64url без дополнения |
| Время | Секунды Unix; поля с суффиксом `_ms` и значения `open_at`, `until` у запечатанных посланий — миллисекунды |
| Имена пользователей | `a–z`, `0–9`, `_`, `.`; 3–32 символа; сравниваются без учёта регистра. Ведущий `@` в путях допускается |

### 1.3. Ошибки

Ошибка — код состояния HTTP и короткий текст причины в теле (`text/plain`). Слой Telegram (раздел 12.3) отвечает в формате Telegram.

| Код | Значение |
|---|---|
| `400` | Неверный запрос: формат, пустое значение, неверный код, неверная подпись ключа |
| `401` | Нет заголовка `Authorization`, неверный или просроченный токен |
| `403` | Нет прав: чужая учётная запись, ретранслятор «только по приглашению», бот не может писать этому пользователю |
| `404` | Нет такого объекта; для `/admin` — панель отключена |
| `409` | Учётная запись с этим адресом уже существует |
| `413` | Превышен предельный размер |
| `429` | Превышена частота запросов |
| `502` | Внешний сервис недоступен (импорт наборов из Telegram) |

### 1.4. Схемы авторизации

| Схема | Заголовок | Кто | Раздел |
|---|---|---|---|
| Сеансовый токен устройства | `Authorization: Bearer <token>` | Клиент Aquamarine | 2 |
| Токен бота | `Authorization: Bot aqbot_…` | Программа бота | 12 |
| Токен администратора | `Authorization: Bearer <AQUA_ADMIN_TOKEN>` | Оператор ретранслятора | 15 |
| Подпись федерации | `x-aqua-fed: <unix_ms>.<hmac>` | Другой ретранслятор сети | 16 |

В таблицах ниже столбец «Доступ» означает: **открытый** — без заголовка; **сеанс** — сеансовый токен; **бот**, **админ**, **федерация** — соответствующая схема.

### 1.5. Предельные значения

| Параметр | Значение |
|---|---|
| Вложение | 210 МиБ |
| Долгоживущее вложение (`?keep=1`) | 4 МиБ |
| Резервная копия | 64 МиБ |
| Изображение профиля | 8 МиБ (анимированное — 3 МиБ) |
| Трек профиля | 10 МиБ |
| Дополнительные поля профиля (`extra`) | 8 КиБ |
| Одноразовые предварительные ключи на устройство | 200 (старые вытесняются) |
| Очередь конвертов на диске | 30 суток |
| Сеансовый токен | 1 ч |
| Запечатанные послания | 50 активных на владельца |
| Текст бота | 4096 символов |

## 2. Аутентификация

Устройство доказывает владение ключом идентичности подписью Ed25519. Пароль на ретранслятор не передаётся; см. [accounts.md](accounts.md).

### 2.1. `POST /v1/auth/challenge` — открытый

```json
{ "identity_dh_pub": "<base64url X25519, 32 байта>" }
```

Ответ — одноразовый nonce (24 байта, действует 60 с):

```json
{ "nonce": "<base64url>" }
```

### 2.2. `POST /v1/auth/verify` — открытый

```json
{
  "identity": { "sign_pub": [/* 32 байта Ed25519 */], "dh_pub": [/* 32 байта X25519 */] },
  "nonce": "<base64url из challenge>",
  "signature": "<base64url подписи Ed25519 над байтами nonce>"
}
```

Ответ:

```json
{ "token": "<base64url>", "expires_at": 1792603600 }
```

Токен — `dh_pub (32) ‖ expires_at (8, BE) ‖ HMAC-SHA256(server_key, dh_pub ‖ expires_at)` в base64url. Ретранслятор проверяет его без хранения состояния. Срок действия — 1 ч; клиент получает новый токен заранее, через 45 мин.

Ошибки: `400` — неверная длина или кодировка; `401` — неверная подпись, nonce не выдавался этому ключу, истёк или уже использован.

### 2.3. Использование

Защищённые запросы передают `Authorization: Bearer <token>`. WebSocket передаёт токен в строке запроса (`?token=…`), потому что браузерный WebSocket не умеет задавать заголовки.

## 3. Предварительные ключи

### 3.1. `POST /v1/bundle/:user` — сеанс

Публикует набор ключей устройства. Ключ идентичности в теле должен совпадать с ключом токена. Первая публикация связывает имя `:user` с ключом; дополнительные устройства публикуют набор по своему адресу `имя~<id>` (см. раздел 7).

```json
{
  "identity":        { "sign_pub": [...], "dh_pub": [...] },
  "signed_prekey":   { "id": 7, "dh_pub": [...], "signature": [/* 64 байта */] },
  "one_time_prekeys": [ { "id": 101, "dh_pub": [...] }, … ]
}
```

Ответ — `204`. Ошибки: `400` — неверная подпись SPK; `403` — ключ набора не совпадает с ключом токена или имя занято другим ключом.

### 3.2. `GET /v1/bundle/:user` — открытый

Выдаёт набор для X3DH и расходует один одноразовый ключ (OPK), если он есть:

```json
{
  "identity": { "sign_pub": [...], "dh_pub": [...] },
  "signed_prekey": { "id": 7, "dh_pub": [...], "signature": [...] },
  "one_time_prekey": { "id": 101, "dh_pub": [...] }
}
```

`one_time_prekey` может быть `null`. Если набора нет локально, ретранслятор запрашивает его у узлов федерации. Клиент обязан проверить подпись SPK до использования. Ошибка: `404`.

## 4. Доставка конвертов (WebSocket)

### 4.1. `GET /v1/ws?user=<адрес>&token=<token>[&ack=1]`

Открывает канал доставки. `user` — имя учётной записи (основное устройство) или адрес дополнительного устройства `имя~<id>`; ретранслятор сам определяет адрес по ключу токена.

После подключения ретранслятор отправляет накопленные конверты: из памяти, из очереди на диске и из очередей узлов федерации. Затем пересылает новые по мере поступления.

`ack=1` (клиенты и ретрансляторы с 1.0.6) включает подтверждения доставки:

1. Первым кадром ретранслятор присылает `{"kind": "ack"}` без `id` — «я подтверждаю».
2. Каждый исходящий кадр клиента несёт случайный `id`. Когда конверт доставлен или сохранён в очередь, ретранслятор отвечает `{"kind": "ack", "id": "<тот же>"}`. Клиент хранит неподтверждённые кадры и после переподключения отправляет их снова. Если подтверждение не приходит 15 с, соединение считается мёртвым.
3. Каждый входящий кадр тоже несёт `id`. Ретранслятор держит его в очереди на диске, пока клиент не ответит `{"kind": "ack", "id": …}`; неподтверждённые приходят снова при следующем подключении. Клиент отбрасывает повторы по `id`.

Без `ack=1` поведение прежнее: подтверждений нет.

### 4.2. Кадр

Кадр — JSON-объект `RelayMessage` в двоичном или текстовом кадре WebSocket:

```json
{ "from": "alice", "to": "bob", "kind": "envelope", "payload": [ /* байты */ ], "ts": 1792858000000, "id": "9f2c…" }
```

| Поле | Значение |
|---|---|
| `from` | Адрес отправителя. В исходящих кадрах ретранслятор заменяет его адресом из токена |
| `to` | Адрес получателя: `имя` или `имя~<id>` |
| `kind` | `initial` — первое сообщение сеанса (X3DH); `envelope` — сообщение Double Ratchet; `plaintext` — открытый текст (только переписка с ботами); `ack` — подтверждение (см. 4.1) |
| `payload` | Для `initial` и `envelope` — сериализованные `InitialMessage` и `Envelope` из `aqua-core::wire`; ретранслятор их не разбирает |
| `ts` | Когда ретранслятор принял кадр от отправителя (мс Unix); ставит ретранслятор |
| `id` | Идентификатор доставки для подтверждений и отбрасывания повторов (необязательный) |

Порядок выбора маршрута — в [delivery.md](delivery.md). Кадры `Ping` получают `Pong`.

## 5. Вложения

| Метод и путь | Доступ | Назначение |
|---|---|---|
| `POST /v1/blob/:cid[?keep=1][&kind=…]` | сеанс | Загрузить шифротекст. `cid` — hex SHA-256 тела; при несовпадении — `400`. Ответ `204`. `kind` (с 1.0.61, необязательно) — грубая метка для панели администратора: `photo`, `video`, `sticker`, `gif`, `emoji`, `voice`, `audio`, `file`; содержимое и имя файла остаются зашифрованными |
| `GET /v1/blob/:cid` | открытый | Получить шифротекст (`application/octet-stream`). При локальном отсутствии ретранслятор запрашивает его у федерации и проверяет хеш |

`keep=1` — долгоживущее вложение (фото и баннеры групп): до 4 МиБ, хранится 90 суток с последнего скачивания. Обычные вложения хранятся `AQUA_BLOB_TTL_HOURS` (по умолчанию 72 ч). Повторная загрузка того же `cid` продлевает срок. Подробнее — [files.md](files.md).

## 6. Учётные записи

### 6.1. Подтверждение адреса

**`POST /v1/auth/email/request`** — открытый.

```json
{ "email": "user@example.com", "purpose": "signup", "nonce": "9f2c…" }
```

`purpose` — `signup`, `signin` или `reset` (поле необязательно). `invite` — код приглашения (необязательно): на сервере «только по приглашениям» адрес, которого нет в списке, проходит с действующим кодом и попадает в список (у кода убавляется одно использование). `nonce` — случайная строка приложения длиной 16–128 символов (необязательно): с ним в письме появляется кнопка «Это я — подставить код», ведущая на `GET /v1/auth/email/link/{token}` по адресу, через который приложение обратилось к ретранслятору (или по `AQUA_PUBLIC_URL`). Ответ:

```json
{ "ok": true, "dev_code": null }
```

Если почтовый сервер не настроен или отказал, ретранслятор в режиме разработки возвращает код в `dev_code` и добавляет `"delivery_failed": true` и `"error"`. Ошибки: `403` — ретранслятор «только по приглашению» и адреса нет в списке; `409` — `signup` для существующего адреса; `404` — `signin` или `reset` для неизвестного адреса.

**`POST /v1/auth/email/verify`** — открытый. `{"email", "code"}` → `{"ok": true, "ticket": "…"}`. Код действует 10 минут, тикет — 30 минут.

**`GET /v1/auth/email/link/{token}`** — страница «Вход в Aquamarine» с кнопкой «Да, это я»; кнопка отправляет `POST` на тот же адрес и подтверждает ссылку. Подтверждение только по кнопке, чтобы почтовые сканеры, открывающие ссылки, не подтверждали её сами.

**`POST /v1/auth/email/poll`** — открытый. `{"email", "nonce"}` → `{"ok": true, "code": "123456"}`, когда ссылка из письма подтверждена, иначе `{"ok": false}`. Код получает только приложение с тем же `nonce`; дальше — обычный `verify`. Приложение опрашивает раз в 2,5 секунды, пока открыт экран ввода кода. Ссылки хранятся в памяти и живут, как код, 10 минут.

### 6.2. Регистрация и вход

| Метод и путь | Доступ | Тело | Ответ |
|---|---|---|---|
| `POST /v1/users/register` | сеанс | `{"ticket", "username", "password", "display_name", "about", "phone"}` | `204` |
| `POST /v1/users/login` | сеанс | `{"ticket", "password", "device_name"}` | `{"username"}` |
| `POST /v1/users/reset` | открытый | `{"ticket", "recovery", "password"}` | `{"username"}` |
| `POST /v1/users/:user/password` | сеанс | `{"password"}` | `204` |
| `POST /v1/me/username` | сеанс | `{"username"}` | `{"ok": true, "username"}` |
| `GET /v1/me` | сеанс | — | `{"username", "uid"}` |
| `GET /v1/users/by-id/:uid` | открытый | — | `{"username", "uid"}`; `404`, если такого ID нет |

- `password` во всех запросах — не пароль, а производный секрет `auth_secret` (Argon2id, см. [accounts.md](accounts.md)).
- `login` добавляет ключ вызывающего устройства к учётной записи как ещё одно устройство.
- `me/username` меняет @имя учётной записи; можно только с основного устройства и не чаще раза в сутки. `@` в начале и регистр не важны; занятое имя — `409`. Ключи, очередь писем, резервная копия и медиа профиля переходят на новое имя; старое имя 30 дней пересылает письма и ключи на новое и не может быть занято другим. Клиент после смены сообщает контактам `[ren:v1]{"old","new"}` в сеансе E2EE, и у них чат и сеансы переходят на новое имя. Ретрансляторы федерации, получив учётную запись под новым именем с тем же ключом, удаляют запись под старым.
- `uid` — ID учётной записи, как в Telegram: 10 цифр, не меняется никогда, даже при смене @имени. Он считается из ключа, с которым учётная запись создана (`SHA-256("aqua-uid\0" ‖ identity_dh)`, первые 8 байт → число), поэтому у старых учётных записей все ретрансляторы получают один и тот же ID. По ID учётные записи сверяются при федерации (см. [federation.md](federation.md)). Приложение спрашивает `GET /v1/me` при подключении: если ретранслятор знает учётную запись под другим @именем, приложение переходит на него.
- `reset` задаёт новый пароль по тикету подтверждённого адреса и проверочному значению ключа восстановления (`recovery`; пустая строка, если у учётной записи ключа нет). Неверный ключ — `403`.

### 6.3. Ключ восстановления

| Метод и путь | Доступ | Назначение |
|---|---|---|
| `GET /v1/me/recovery` | сеанс | `{"set": true}` — у учётной записи есть ключ восстановления |
| `PUT /v1/me/recovery` | сеанс | `{"check": "<hex>"}` — сохранить проверочное значение. Ретранслятор хранит только его хеш |

`check` = HKDF-SHA256(энтропия 24 слов, info = `aquamarine account recovery v1`). Из него нельзя получить ключ резервной копии.

### 6.4. Поиск

`GET /v1/users/search?q=<строка>` — открытый. До 20 профилей (раздел 8), найденных по имени пользователя и отображаемому имени. `@` в начале запроса не учитывается, `_` и `%` — обычные символы; точное совпадение — первым. Старое @имя (после смены) находит учётную запись под новым, ID (10 цифр) — учётную запись с этим ID.

## 7. Устройства

| Метод и путь | Доступ | Назначение |
|---|---|---|
| `GET /v1/devices/:user` | открытый | Устройства учётной записи — адреса для шифрования |
| `GET /v1/me/devices` | сеанс | Свои устройства; текущее отмечено `"current": true` |
| `POST /v1/me/devices/:id` | сеанс | `{"name"}` — переименовать дополнительное устройство |
| `DELETE /v1/me/devices/:id` | сеанс | Отключить устройство: его соединения закрываются, очередь и ключи удаляются |

Элемент списка:

```json
{ "addr": "alice~a1b2c3d4e5f6", "id": "a1b2c3d4e5f6", "primary": false,
  "name": "Pixel 8", "added": 1792000000, "online": true }
```

`id` — первые 6 байт ключа DH устройства в hex. Отключить текущее устройство нельзя (`400`): это делается с другого. Отключение основного делает основным устройство, с которого выполнен запрос.

## 8. Профили и медиа профиля

### 8.1. Профиль

`GET /v1/users/:user/profile` — открытый:

```json
{
  "username": "alice", "display_name": "Alice", "about": "…", "phone": "",
  "is_bot": false, "created_at": 1791000000,
  "extra": { "status": "…", "games": ["Teardown"], "game_ids": {"Teardown": "1124…"} },
  "avatar_ver": 3, "banner_ver": 0, "music_ver": 1, "uid": "4821937710"
}
```

`POST /v1/users/:user/profile` — сеанс, только владелец: `{"display_name", "about", "phone", "extra"}`. Если `extra` не передан, прежнее значение сохраняется. `extra` — произвольный объект до 8 КиБ: цвета баннера, статус, любимые игры, ссылки и т. п. Поле `extra.es` — эмодзи-статус (эмодзи или токен `ce:<набор>/<файл>|<эмодзи>`): `""` и `"-"` превращаются в `null`, длиннее 160 символов, с переводом строки или `<>` — `400`; смена чаще 30 раз в час — `429`.

### 8.2. Медиа

`:kind` — `avatar`, `banner` или `music`.

| Метод и путь | Доступ | Назначение |
|---|---|---|
| `GET /v1/users/:user/media/:kind` | открытый или сеанс | Файл с его типом MIME. Если владелец ограничил доступ, ответ зависит от того, кто спрашивает |
| `POST /v1/users/:user/media/:kind` | сеанс, владелец | Тело — файл, `Content-Type` — его тип. Ответ `{"ok": true, "ver": 4}` |
| `DELETE /v1/users/:user/media/:kind` | сеанс, владелец | Удалить |
| `POST /v1/users/:user/media_acl` | сеанс, владелец | `{"everybody": false, "allow": ["bob"], "deny": []}` — кому доступны медиа профиля; до 5000 имён |

## 9. Резервные копии

Копия шифруется на устройстве (формат `AQBK1`, см. [backups.md](backups.md)); ретранслятор хранит байты, которые не может прочитать.

| Метод и путь | Доступ | Назначение |
|---|---|---|
| `PUT /v1/backup` | сеанс | Тело — копия (до 64 МиБ, начинается с `AQBK1`). Ответ `{"size", "updated_at"}` |
| `GET /v1/backup` | сеанс | `{"exists": true, "size", "updated_at"}` или `{"exists": false}` |
| `DELETE /v1/backup` | сеанс | Удалить копию |
| `POST /v1/backup/fetch` | открытый | `{"ticket", "password"}` → копия (`application/octet-stream`). Для нового устройства, у которого ещё нет ключа идентичности |

## 10. Запечатанные послания

Ключ послания хранится на ретрансляторе отправителя вместе с условием открытия; сам текст получатель получает сразу, в зашифрованном виде. Подробнее — [sealed-messages.md](sealed-messages.md).

### 10.1. `PUT /v1/capsules` — сеанс

```json
{ "id": "cap-0a1b2c3d4e5f60718293", "recipient": "bob",
  "key": "<64 hex-символа>", "kind": "inactive",
  "open_at": 0, "days": 30, "grace_h": 48 }
```

| Поле | Ограничения |
|---|---|
| `id` | 8–64 символа `A–Z a–z 0–9 - _`, уникален |
| `kind` | `date` — открыть в момент `open_at` (мс Unix); `inactive` — открыть, если отправитель не подключался `days` суток (1–3650) |
| `grace_h` | 0–720: сколько часов после запроса получателя у отправителя есть, чтобы отказать |

Ответ `204`. Не более 50 активных посланий на владельца.

### 10.2. `GET /v1/capsules` — сеанс

Свои послания без ключей: `[{ "id", "recipient", "kind", "open_at", "days", "grace_h", "created", "requested", "released", "cancelled" }]`. `created`, `requested`, `released` — мс Unix (0 — не было), `cancelled` — логическое.

### 10.3. `POST /v1/capsules/:id/open` — сеанс, только получатель

| Ответ | Значение |
|---|---|
| `{"state": "open", "key": "<hex>"}` | Условие выполнено — ключ выдан |
| `{"state": "sealed", "until": <мс>}` | Дата ещё не наступила |
| `{"state": "sealed", "inactive_days": 30}` | Отправитель был в сети недавно или подключён сейчас |
| `{"state": "waiting", "until": <мс>}` | Условие выполнено, идёт окно для отказа; первый запрос запускает его |
| `{"state": "cancelled"}` | Отправитель отменил послание |

### 10.4. `POST /v1/capsules/:id/stop` — сеанс, только отправитель

`{"forever": false}` — отклонить текущий запрос (окно начнётся заново при следующем); `{"forever": true}` — отменить послание навсегда. Ответ `204`; `404` — нет такого послания или оно уже открыто.

| Метод и путь | Доступ | Назначение |

## 12. Боты

### 12.1. Управление (владелец)

| Метод и путь | Доступ | Тело | Ответ |
|---|---|---|---|
| `POST /v1/bot/register` | сеанс | `{"username", "display_name"}` | `{"ok", "username", "token", "telegram_token"}` |
| `GET /v1/bot/list` | сеанс | — | `[{"username", "display_name", "token": "", "hint"}]` |

Повторная регистрация существующего бота того же владельца выпускает новый токен. Ретранслятор хранит только SHA-256 токена; `hint` — последние 4 символа.

### 12.2. API бота

| Метод и путь | Доступ | Назначение |
|---|---|---|
| `GET /v1/bot/me` | бот | `{"username", "display_name", "id"}` |
| `GET /v1/bot/updates?after=N&timeout=25` | бот | Длинный опрос (до 30 с). Ответ — `[{"id", "from", "text", "ts", "callback"?, "callback_msg"?}]`; `after` подтверждает обновления с меньшим `id` |
| `POST /v1/bot/send` | бот | `{"to", "text"}` → `204`; с `parse_mode`, `buttons`, `keyboard`, `remove_keyboard` → `{"message_id"}` |
| `POST /v1/bot/edit` | бот | `{"to", "text", "message_id"?, "buttons"?, "parse_mode"?}` → `{"message_id"}` |
| `POST /v1/bot/broadcast` | бот | `{"text", "parse_mode"?, "buttons"?}` → `202 {"queued"}`: всем контактам, в фоне, в пределах лимитов |
| `GET /v1/bot/contacts` | бот | `[{"username", "display_name", "id"}]` — кому бот может писать |
| `GET /v1/bot/user/:name` | бот | `{"username", "display_name", "id", "is_bot", "is_contact"}` |
| `GET, POST, DELETE /v1/bot/commands` | бот | Меню команд: `[{"command", "description"}]` или `{"команда": "описание"}` |
| `GET, POST, DELETE /v1/bot/webhook` | бот | `{"url", "secret"?, "drop_pending"?}`; `GET` — как `getWebhookInfo` |
| `GET, POST /v1/bot/profile` | бот | `{"description"?, "short_description"?}` |
| `GET /v1/bot/stats` | бот | `{"username", "contacts", "pending_updates", "webhook", "commands"}` |
| `POST /v1/bot/call/:method` | бот | Любой метод Telegram Bot API с заголовком `Authorization: Bot`; ответ `{"ok", "result"}` |

Бот пишет только тем, кто писал ему (и владельцу); `/stop` отзывает разрешение. Частота: 30 сообщений/с на бота, 1/с на чат (всплеск 5), опрос — 5/с. Подробно — [bots.md](bots.md).

### 12.3. Слой Telegram Bot API

`GET|POST /bot<токен>/<метод>` — те же методы и форматы, что у `api.telegram.org`. Токен — `<число>:aqbot_…` (поле `telegram_token`). Поддерживаемые методы, вебхуки и соответствие понятий — в [bots.md, раздел 9](bots.md#9-совместимость-с-telegram-bot-api).

## 15. Статистика и администрирование

`GET /v1/stats` — открытый: `{"ok", "users", "bots", "online", "require_registration"}`. Только счётчики, без имён.

Панель администратора и её API доступны, если задан `AQUA_ADMIN_TOKEN` (иначе `404`). Запросы API передают `Authorization: Bearer <AQUA_ADMIN_TOKEN>`.

| Метод и путь | Назначение |
|---|---|
| `GET /admin` | Веб-панель |
| `GET /v1/admin/stats` | Адрес, IP в локальной сети, счётчики, объём вложений, время работы, последние коды подтверждения (в режиме разработки; просроченные — старше 10 минут — не показываются), режим приглашений |
| `GET /v1/admin/detail/:what` | Что открывает плитка панели: `online` — @имена в сети; `files` — `[{kind, count, bytes}]` по типам (без метки — `unknown`); `bots` — `[{username, name}]`; `visitors` — серверы и люди федерации, обращавшиеся к узлу с момента запуска; `journal` — последние 500 событий `{at, user, ev, note}` (`online`, `offline`, `login`, `register`). Журнал дописывается и в файл `AQUA_JOURNAL` (по умолчанию `aqua-journal.log`, `off` — не писать) |
| `GET` / `POST /v1/admin/datadir` | Папка данных: `{path, bytes, suggest}`. `POST {"path": "…"}` копирует данные в другую папку и запоминает её — она используется со следующего запуска; старая остаётся |
| `POST /v1/admin/config` | `{"invite_only", "allow": [адреса]}` — режим «только по приглашению» |
| `GET /v1/admin/invites` | Коды приглашений: `[{"code", "uses", "expires", "note"}]` |
| `POST /v1/admin/invites` | `{"uses", "days", "note"}` → новый код. Панель показывает его QR: `aqua:join?s=<адрес сервера>&c=<код>` |
| `DELETE /v1/admin/invites/:code` | Удалить код |
| `GET`, `POST /v1/admin/smtp` | Настройки почтового сервера (пароль в ответе не возвращается) |
| `POST /v1/admin/smtp/test` | `{"to"}` — отправить пробное письмо |
| `GET`, `POST /v1/admin/telegram` | Токен бота Telegram для импорта наборов: `{"token"}` |
| `GET`, `POST /v1/admin/federation` | `{"mode": "solo"\|"network", "secret", "peers": [адреса], "public_url"}`; секрет не короче 16 символов и в ответе не возвращается. `mode: "network"` без секрета создаёт его сам. В ответе GET также `smtp` — есть ли у узла своя почта |
| `GET /v1/admin/fed/invite` | `{"invite"}` — код приглашения в сеть `aquafed:…` (адрес узла и секрет сети) |
| `POST /v1/admin/fed/join` | `{"invite"}` — войти в сеть по коду: узел берёт секрет, добавляет пригласившего соседом и знакомится с остальными |
| `GET /v1/admin/servers` | Другие ретрансляторы: соседи, найденные в локальной сети (`/24`) и в публичном списке; для каждого `url`, `found`, `peer`, `ok`, `ms`, `users`, `online`, `same_network` |

## 16. Федерация

Межсерверные запросы подписываются общим секретом сети:

```
x-aqua-fed: <unix_ms>.<hex HMAC-SHA256(secret, METHOD "\n" PATH "\n" unix_ms "\n" hex(SHA-256(body)))>
```

Расхождение часов — не более ±5 минут. Запрос без верной подписи отклоняется.

| Метод и путь | Назначение |
|---|---|
| `GET /v1/fed/peers` | Публичные адреса узлов сети (без подписи — для переключения клиентов) |
| `POST /v1/fed/poke` | «У меня изменения» — получатель сразу выполняет выборку |
| `GET /v1/fed/users?since=` | Строки учётных записей с `updated_at` больше курсора (страницами по 500) |
| `GET /v1/fed/backups?since=` | Метаданные резервных копий |
| `GET /v1/fed/backup/:user` | Резервная копия |
| `GET /v1/fed/media/:user/:kind` | Медиа профиля |
| `POST /v1/fed/deliver` | Доставить конверт получателю, подключённому к этому узлу |
| `GET /v1/fed/inbox/:user` | Забрать конверты, ждущие получателя на этом узле |
| `GET /v1/fed/bundle/:user` | Набор ключей (без OPK) |
| `GET /v1/fed/blob/:cid` | Шифротекст вложения |
| `POST /v1/fed/hello` | `{"url", "peers": [адреса]}` — «я в сети»: получатель добавляет отправителя и тех из его соседей, кто отвечает с тем же секретом |
| `GET /v1/fed/ping` | Проверка «в той же сети» (`204` при верной подписи) |
| `POST /v1/fed/mail` | `{"to", "code", "link"}` — отправить письмо с кодом подтверждения за узел без своей почты (не больше 5 писем на адрес за 10 минут) |

Протокол — в [federation.md](federation.md).

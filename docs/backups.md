# Резервное копирование и перенос учётной записи

> Часть [технической документации](README.md). Реализация — `crates/aqua-client-core/src/backup.rs`, `crates/aqua-client-ui/src/backups.rs`.

## 1. Назначение

Зашифрованная резервная копия решает две задачи:

- переносит на новое устройство историю, группы, контакты и настройки;
- восстанавливает учётную запись, если все устройства утрачены.

Ключ идентичности и сеансы из копии на новое устройство не переносятся: устройство сохраняет собственные ключи и входит как ещё одно устройство учётной записи ([accounts.md](accounts.md#4-несколько-устройств)).

Ретранслятор хранит копию, но расшифровать её не может.

## 2. Формат `AQBK1`

```
"AQBK1" ‖ u32 BE длина_заголовка ‖ заголовок (JSON) ‖ nonce[12] ‖ ChaCha20-Poly1305(DEK, nonce, AAD = "AQBK1", DEFLATE(payload))
```

| Поле заголовка | Содержимое |
|---|---|
| `kdf` | Параметры Argon2id: соль 16 байт, m = 64 МиБ, t = 3, p = 1. Хранятся в заголовке, чтобы их можно было усилить позже |
| `pw` | DEK, обёрнутый ключом Argon2id(пароль) |
| `rk` | DEK, обёрнутый ключом HKDF-SHA256(энтропия ключа восстановления, info = `aquamarine backup recovery v1`) |
| `created` | Время создания, секунды Unix |

Ключи:

- **DEK** — случайный 256-битный ключ данных.
- **Ключ восстановления** — 256 бит энтропии; пользователь получает его один раз в виде 24 слов словаря BIP-39.

Копию открывает любой из двух ключей: пароль или ключ восстановления. Ключ входа ([accounts.md](accounts.md#2-регистрация-и-пароль)) и ключ копии вычисляются с разными солями и параметрами, поэтому знание `auth_secret` не позволяет вычислить ключ копии. Проверочное значение для сброса пароля выводится из ключа восстановления с другой меткой HKDF и тоже не открывает копию.

## 3. Содержимое и периодичность

| Параметр | Значение |
|---|---|
| Входит в копию | Записи хранилища (идентичность, сеансы, SPK, OPK, история, группы, токены ботов) и настройки интерфейса (включая пароли чатов, папки, закрепления, приватность) |
| Не входит в копию | Медиафайлы и локальный медиакэш |
| Предельный размер | 64 МиБ |
| Периодичность | Через ≈ 20 с после важного изменения (группы, контакты, профиль, настройки, папки, закрепления, приватность) — не чаще раза в 2 мин; после новых сообщений — не чаще раза в 20 мин; не реже раза в 6 ч; при закрытии приложения, если были изменения; по команде пользователя |
| Включение | По умолчанию при регистрации и входе по паролю; отключается в настройках |
| Методы | `PUT`, `GET`, `DELETE /v1/backup`; `POST /v1/backup/fetch` (по тикету подтверждённого адреса и `auth_secret`) |

## 4. Перенос на новое устройство

1. Пользователь подтверждает адрес электронной почты и вводит пароль.
2. Клиент загружает копию и расшифровывает её паролем. Если пароль изменён или утрачен, используется ключ восстановления.
3. Записи хранилища импортируются, кроме ключа идентичности, предварительных ключей и сеансов этого устройства; состояние клиента перестраивается. Ключ устройства добавляется к учётной записи.

Если ретранслятор недоступен, те же действия выполняются через другой узел федерации: копии реплицируются ([federation.md](federation.md)).

# Протокол сквозного шифрования

> Часть [технической документации](README.md). Реализация — `crates/aqua-core`.

## 1. Криптографические примитивы

| Назначение | Алгоритм | Стандарт | Реализация |
|---|---|---|---|
| Согласование ключей | X25519 | RFC 7748 | `x25519-dalek` 2.0 |
| Подпись | Ed25519 | RFC 8032 | `ed25519-dalek` 2.2 |
| Аутентифицированное шифрование | ChaCha20-Poly1305, nonce 96 бит | RFC 8439 | `chacha20poly1305` 0.10 |
| Выработка ключей | HKDF-SHA256 | RFC 5869 | `hkdf` 0.12 |
| Цепочки ключей, токены, подпись запросов федерации | HMAC-SHA256 | RFC 2104 | `hmac` 0.12 |
| Идентификатор файла, хеш токена бота | SHA-256 | FIPS 180-4 | `sha2` 0.10 |
| Ключ резервной копии, производный секрет входа | Argon2id v1.3 | RFC 9106 | `argon2` 0.5 |
| Хранение секрета входа на сервере | PBKDF2-HMAC-SHA256, 120 000 итераций, соль 16 байт | RFC 8018 | собственная обёртка над `hmac` |
| Сжатие истории и копий | DEFLATE | RFC 1951 | `flate2` 1.1 |
| Ключ восстановления | 256 бит энтропии → 24 слова BIP-39 | BIP-0039 | собственная реализация |
| Сравнение секретов | Постоянное время | — | `subtle` 2.6 |
| Очистка памяти | Обнуление при освобождении | — | `zeroize` 1.9 |
| Запечатанные послания, пароли чатов (в интерфейсе) | AES-256-GCM; PBKDF2-SHA256 | NIST SP 800-38D; RFC 8018 | WebCrypto |

Протокол собран из перечисленных примитивов без `libsignal` и `vodozemac`. С протоколами Signal и Matrix (Olm/Megolm) он несовместим.

## 2. Ключи

Идентичность устройства — две независимые пары ключей:

- **IK_sig** (Ed25519) — подпись предварительных ключей и ответов на запрос аутентификации;
- **IK_dh** (X25519) — участие в X3DH.

В Signal одна пара выводится из другой (XEdDSA). Раздельные пары упрощают реализацию ценой 32 дополнительных байт в наборе ключей.

| Ключ | Описание | Политика |
|---|---|---|
| IK | Идентичность устройства (Ed25519 + X25519) | Постоянный; у каждого устройства свой |
| SPK | Подписанный предварительный ключ X25519 | Ротация каждые 7 суток |
| OPK | Одноразовые предварительные ключи X25519 | При остатке менее 10 пополняются до 50; на ретрансляторе — не более 200 |

## 3. X3DH

```
DH1 = DH(IK_A, SPK_B)   DH2 = DH(EK_A, IK_B)   DH3 = DH(EK_A, SPK_B)   DH4 = DH(EK_A, OPK_B)  (при наличии OPK)
SK  = HKDF-SHA256(salt = 0^32, ikm = 0xFF^32 ‖ DH1 ‖ DH2 ‖ DH3 [‖ DH4], info = "Aquamarine/X3DH v1", L = 32)
AD  = IK_A(X25519) ‖ IK_B(X25519)
```

Подпись SPK проверяется до использования ключа. Получатель уничтожает использованный OPK. AD входит в AAD каждого шифротекста сеанса.

Первое сообщение сеанса — `InitialMessage`: ключ идентичности и эфемерный ключ отправителя, номер использованного OPK, заголовок храповика и шифротекст. Последующие — `Envelope`: заголовок и шифротекст (`aqua-core/src/wire.rs`).

## 4. Double Ratchet

| Элемент | Реализация |
|---|---|
| Корневая цепочка | HKDF-SHA256, метка `Aquamarine/RootKDF v1` |
| Цепочки сообщений | HMAC-SHA256; байт `0x01` — ключ сообщения, байт `0x02` — следующий ключ цепочки |
| Ключ сообщения | HKDF, метка `Aquamarine/MsgKey v1` |
| Шифрование | ChaCha20-Poly1305 |

Свойства:

- **Прямая секретность.** Ключ сообщения используется однократно и уничтожается.
- **Восстановление после компрометации.** Каждый новый ключ DH собеседника подмешивает в корневой ключ свежий результат Диффи–Хеллмана.
- **Внеочередные сообщения.** Хранится до 1000 ключей пропущенных сообщений (`MAX_SKIP`). При превышении расшифровка прекращается с явной ошибкой.

## 5. Несколько устройств

У каждого устройства собственные IK, SPK, OPK и собственные сеансы. Отправитель шифрует сообщение отдельно для каждого устройства собеседника и для каждого своего устройства (обёртка `[sync:v1]`). Закрытые ключи между устройствами не передаются. Подробнее — [accounts.md](accounts.md#4-несколько-устройств).

## 6. Группы

Сообщение в группу шифруется отдельно для каждого участника его парным сеансом (fan-out); групповых ключей нет. Стоимость отправки растёт как O(N). Состояние группы хранится только у участников — [groups.md](groups.md).

## 7. Проверка собеседника

Окно «Отпечаток» показывает:

- полный открытый ключ X25519 собеседника в шестнадцатеричной записи;
- последовательность из 8 слов.

Защиту от подмены ключа ретранслятором даёт только сверка полной шестнадцатеричной записи по независимому каналу. Слова — визуальная подсказка без криптостойкости: каждое кодирует один байт по модулю 24.

## 8. Сравнение с Signal

| Свойство | Signal | Aquamarine |
|---|---|---|
| Согласование | X3DH (XEdDSA) | X3DH, раздельные ключи подписи и DH |
| Храповик | Double Ratchet | Double Ratchet (HMAC-цепочки, HKDF) |
| Шифр | AES-256-CBC + HMAC | ChaCha20-Poly1305 |
| Группы | Sender Keys | Попарная рассылка |
| Постквантовая защита | PQXDH (ML-KEM) | Нет |
| Запечатанный отправитель | Есть | Нет: ретранслятор видит отправителя |

# COMPLETE FUNCTIONAL AUDIT — AQUAMARINE

## 1. Цель

Создать максимально полную карту функциональности Aquamarine.

Сравнить с:

- Telegram.
- Signal.
- WhatsApp.
- Element X.
- Briar.

Цель — определить не просто количество функций, а реальное качество и полноту реализации.

## 2. Правила исследования

Для каждой функции определить:

1. Существует ли функция.
2. Где реализована.
3. Есть ли серверная часть.
4. Есть ли клиентская часть.
5. Есть ли API.
6. Работает ли она фактически.
7. Какие ограничения существуют.
8. Есть ли ошибки.
9. Как реализована у конкурентов.
10. Что необходимо улучшить.

Статусы:

- FULL — полностью реализована.
- PARTIAL — частично реализована.
- UI ONLY — только интерфейс.
- BACKEND ONLY — только серверная часть.
- BROKEN — присутствует, но не работает корректно.
- MISSING — отсутствует.
- UNVERIFIED — не проверена.

Не ставить FULL без реального тестирования.

# UI/UX, ANIMATIONS & ANDROID QUALITY

## 1. Цель

Сделать интерфейс CeZeOs и Aquamarine визуально целостным, современным, отзывчивым и технически качественным.

Не создавать упрощённый интерфейс ради скорости разработки.

Не превращать Aquamarine в копию Telegram.

Сохранять самостоятельную визуальную идентичность проекта.

## 2. Полный UI-аудит

Проверить:

* Все страницы.
* Все экраны.
* Все диалоги.
* Все модальные окна.
* Контекстные меню.
* Списки.
* Карточки.
* Формы.
* Поиск.
* Уведомления.
* Состояния загрузки.
* Состояния ошибок.
* Пустые состояния.

Проверить все интерактивные элементы.

Нельзя оставлять кнопки, которые визуально существуют, но ничего не делают.

## 3. Дизайн-система

Проверить и привести к согласованной системе:

* Typography.
* Spacing.
* Radius.
* Shadows.
* Colors.
* Borders.
* Icons.
* Component states.
* Light theme.
* Dark theme.
* Accessibility.

Не допускать случайных различий между одинаковыми компонентами.

## 4. Анимации

Анимации должны быть осмысленными и соответствовать действиям пользователя.

Реализовать и проверить, где это уместно:

* Переходы между экранами.
* Переходы между чатами.
* Открытие и закрытие окон.
* Появление меню.
* Переключение вкладок.
* Отправка сообщений.
* Получение сообщений.
* Реакции.
* Закрепления.
* Ответы.
* Разворачивание тредов.
* Переключение тем.
* Галереи.
* Просмотр изображений.
* Видеоплеер.
* Загрузка файлов.
* Прогресс загрузки.
* Ошибки.
* Уведомления.
* Изменение состояния кнопок.

Не анимировать всё подряд.

## 5. Требования к качеству анимаций

Использовать:

* Подходящие easing curves.
* Естественную длительность.
* Согласованную динамику.
* Правильную иерархию переходов.
* Ненавязчивые микровзаимодействия.

Не допускать:

* Резких скачков.
* Дрожания.
* Мерцания.
* Непредсказуемого изменения layout.
* Конфликтующих переходов.
* Двойного запуска.
* Застревания анимации.
* Блокировки интерфейса.

Предпочитать transform и opacity там, где это оправдано.

## 6. Производительность анимаций

Проверить:

* FPS.
* Frame time.
* Dropped frames.
* Layout recalculations.
* Repaints.
* Compositing.
* GPU utilization.
* RAM.
* JS main thread.
* Rust backend load.

Целевой ориентир для плавных переходов — 60 FPS на устройствах с поддержкой 60 Гц, с корректной адаптацией к экранам с более высокой частотой обновления.

Не считать 60 FPS универсальной гарантией для каждого устройства.

Анимации должны корректно работать при слабом процессоре и высокой нагрузке.

## 7. Управление жизненным циклом

Обязательно:

* Останавливать анимации при уничтожении компонентов.
* Очищать таймеры.
* Удалять обработчики событий.
* Не создавать повторные подписки.
* Не допускать утечек.
* Обрабатывать быстрые повторные действия.
* Поддерживать прерывание переходов.

Учитывать prefers-reduced-motion.

## 8. Svelte и Tauri

Исследовать:

* Svelte 5 reactivity.
* Component lifecycle.
* Transitions.
* Stores.
* Derived state.
* Tauri IPC.
* WebView rendering.
* Rust background tasks.

Проверить, не вызывают ли повторные обновления состояния ненужные перерисовки.

Не выполнять тяжёлые операции на главном потоке интерфейса.

## 9. Android

Провести отдельный аудит Android-клиента.

Проверить:

* Адаптивность.
* Жесты.
* Клавиатуру.
* Insets.
* Safe areas.
* Background behavior.
* Notification permissions.
* Push tokens.
* Notification channels.
* Battery optimization.
* Doze.
* Foreground services.
* Deep links.
* Возобновление приложения.

## 10. Android-уведомления

Проверить полную цепочку доставки уведомления.

Сценарии:

* Приложение открыто.
* Приложение свёрнуто.
* Приложение закрыто.
* Устройство заблокировано.
* Устройство перезапущено.
* Нет сети.
* Сеть восстановлена.
* Токен обновлён.
* Пользователь отключил канал уведомлений.

Проверить Android 13+ и актуальные ограничения более новых версий Android.

Не считать исправлением ситуацию, когда уведомления приходят только при открытом приложении.

## 11. UX-тестирование

Проверить:

* Быстрые действия.
* Переключение чатов.
* Скроллинг.
* Отправку сообщений.
* Открытие файлов.
* Навигацию.
* Ошибки.
* Повторные нажатия.
* Переходы при плохой сети.

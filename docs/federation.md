# Федерация ретрансляторов

> Часть [технической документации](README.md). Реализация — `crates/aqua-server/src/fed.rs`; методы — [api.md](api.md#16-федерация).

## 1. Принцип

Ретранслятор — «почтальон»: он видит конверты, публичные профили и зашифрованные файлы, но не содержимое. Поэтому ретрансляторов может быть несколько и им не нужно доверять друг другу больше, чем одному. Несколько ретрансляторов образуют единую сеть: пользователь любого узла пишет пользователю любого другого, а при отказе узла клиент переходит на соседний.

## 2. Настройка

Узлы сети используют:

- общий секрет — `AQUA_FED_SECRET` или панель администратора (не короче 16 символов);
- перечень адресов соседей — `AQUA_FED_PEERS` (через запятую);
- свой публичный адрес — `AQUA_PUBLIC_URL` (его узнают клиенты и соседи).

Настройки из панели хранятся в `aqua-federation.json` и применяются без перезапуска.

## 3. Подпись запросов

Каждый межсерверный запрос подписывается заголовком:

```
x-aqua-fed: <unix_ms>.<hex HMAC-SHA256(secret, METHOD "\n" PATH "\n" unix_ms "\n" hex(SHA-256(body)))>
```

Допустимое расхождение часов — ±5 минут. Подпись покрывает метод, путь с параметрами и тело.

## 4. Функции

| Функция | Механизм |
|---|---|
| Уведомление об изменении | Узел раз в 1,5 с сравнивает отметку изменений (наибольшие `updated_at` таблиц `users` и `backups`). Если она сдвинулась, узел отправляет соседям `POST /v1/fed/poke`, и они сразу выполняют выборку. Без уведомлений выборка выполняется каждые 30 с |
| Репликация учётных записей | Узлы забирают у соседей строки `users` с `updated_at` больше курсора (страницами по 500); при конфликте побеждает более поздняя запись. Учётные записи ботов не реплицируются |
| Репликация медиа профилей | Если у принятой строки изменилась версия аватара, баннера или трека, узел сразу копирует файл у соседа и хранит у себя |
| Репликация резервных копий | Тем же способом, по `updated_at` |
| Доставка | Конверт пересылается узлу, к которому подключён получатель (`POST /v1/fed/deliver`). Если получатель не в сети ни на одном узле, конверт ждёт на исходном узле; узел, к которому получатель подключится, забирает его (`/v1/fed/inbox/:user`) |
| Ключи, вложения | При локальном отсутствии запрашиваются у соседей; целостность вложений проверяется по CID. Одноразовые ключи (OPK) не реплицируются, чтобы один ключ не был выдан дважды |
| Отказоустойчивость клиента | `GET /v1/fed/peers` возвращает публичные адреса узлов. Клиент хранит до 12 адресов и при недоступности текущего узла переподключается к следующему |

Не реплицируются: учётные записи ботов и их очереди, наборы стикеров (каждый узел импортирует свои), запечатанные послания и время последнего подключения ([sealed-messages.md](sealed-messages.md#5-ограничения)).

## 5. Режимы доступа

| Режим | Кто может зарегистрироваться | Включение |
|---|---|---|
| Открытый | Любой адрес электронной почты | По умолчанию |
| «Только по приглашению» | Адреса из белого списка | Панель администратора (`POST /v1/admin/config`), хранится в `aqua-admin.json` |

Режим ограничивает регистрацию на своём узле и не затрагивает E2EE.

## 6. Подключение через прокси

Клиент направляет весь трафик к ретранслятору (HTTP и WebSocket) через SOCKS5, если адрес задан в «Настройки → Аккаунт и сервер → Подключение через сервер»: `socks5://` или `socks5h://` (имена разрешает прокси). Клиент сам туннель не поднимает — подходит любой локальный SOCKS5, например конец туннеля до своего узла за пределами фильтрующей сети.

## 7. Проверка

Интеграционные тесты `crates/aqua-server/tests/federation.rs` запускают два узла в одном процессе. Тест `changes_are_pushed_to_peers` проверяет, что учётная запись, аватар и резервная копия доходят до второго узла без ручной синхронизации, а ключи переживают перезапуск.

## 8. Направления развития

Не реализовано; порядок может меняться:

1. Идентичность узла (ключ Ed25519) и обмен списком узлов с подписью (gossip) вместо статического `AQUA_FED_PEERS`.
2. «Домашние» узлы получателя (2–3 по rendezvous-хешу имени) для офлайн-очередей.
3. Координатор каталога с выбором преемника по репутации (аптайм, успешные доставки).
4. Пограничный ретранслятор в разрешённой сети, который только пересылает TLS на узлы сети.
5. Подключаемые транспорты (маскировка трафика) и маршрутизация по соседям (Kademlia).
6. Ретранслятор на телефоне и встроенный узел в клиенте.

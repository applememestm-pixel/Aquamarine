# Запечатанные послания

> Часть [технической документации](README.md). Методы — [api.md](api.md#10-запечатанные-послания). Реализация — `ui/src/lib/capsules.ts`, `crates/aqua-server/src/directory.rs` (`capsule_*`).

Запечатанное послание приходит получателю сразу, но открывается позже: в выбранную дату или если отправитель пропал — не подключался к ретранслятору заданное число дней. Отправитель может оставить себе время отказать, когда получатель попросит открыть.

## 1. Разделение знания

1. Клиент отправителя генерирует случайный 256-битный ключ и nonce и шифрует текст AES-256-GCM (WebCrypto).
2. Ключ вместе с условием сохраняется на ретрансляторе отправителя: `PUT /v1/capsules`.
3. Получателю уходит обычное сообщение E2EE `[capsule:v1]` с шифротекстом, подписью на конверте, условием и адресом ретранслятора:

   ```json
   {"id", "ct", "iv", "hint", "kind": "date"|"inactive", "open_at"?, "days"?, "grace_h", "relay", "from"}
   ```

4. Получатель нажимает «Попробовать открыть» — `POST /v1/capsules/:id/open` на ретранслятор из `relay`. Когда условие выполнено, ретранслятор выдаёт ключ, и текст расшифровывается на устройстве.

По отдельности ни ретранслятор (ключ без текста), ни получатель (текст без ключа) прочитать послание раньше срока не могут.

## 2. Условия

| Условие | Когда выполнено |
|---|---|
| `date` | Наступил момент `open_at` (мс Unix) |
| `inactive` | Ни одно устройство отправителя сейчас не подключено к ретранслятору, и с последнего подключения прошло не меньше `days` суток (1–3650) |

Время последнего подключения ретранслятор отмечает при открытии и закрытии каждого WebSocket (таблица `last_seen`).

## 3. Окно для отказа

Если `grace_h > 0` (до 720 ч), выполнение условия не открывает послание сразу:

1. первый запрос получателя запускает окно и возвращает `{"state": "waiting", "until": …}`;
2. у отправителя появляется предупреждение «@имя хочет открыть ваше запечатанное послание» с кнопками «Отказать» и «Пусть откроется»;
3. «Отказать» (`/stop` с `forever: false`) сбрасывает запрос — окно начнётся заново при следующем запросе;
4. по истечении окна следующий запрос получателя получает ключ.

Отправитель может отменить послание навсегда (`forever: true`): ретранслятор больше не выдаст ключ, и послание открыть нельзя.

## 4. Хранение

| Где | Что |
|---|---|
| Ретранслятор отправителя | Таблица `capsules`: идентификатор, владелец, получатель, ключ (hex), условие, окно, время создания, запроса, выдачи, отмены. Не более 50 активных посланий на владельца |
| Получатель | Сообщение `[capsule:v1]` в зашифрованной истории; открытый текст после открытия — в настройках интерфейса этого устройства |
| Отправитель | Список своих посланий без ключей (`GET /v1/capsules`) |

## 5. Ограничения

1. Ключ хранится на ретрансляторе открыто (он должен уметь выдать его без участия отправителя). Оператор ретранслятора отправителя, получивший и текст (например, с устройства получателя), прочтёт послание раньше срока.
2. Послания и время последнего подключения не реплицируются федерацией. Если отправитель работает через другой узел сети, ретранслятор, на котором лежит ключ, видит его неактивным: условие `inactive` может выполниться, хотя отправитель в сети. Окно для отказа помогает, только если отправитель подключён к тому же ретранслятору, где лежит ключ. Для условия `inactive` при федерации рекомендуется окно не меньше 48 ч и работа через один ретранслятор.
3. Если ретранслятор отправителя недоступен, послание нельзя открыть, пока он не вернётся.
4. Отправка — только в личные чаты.

# Подпись выпусков (AQUA-SEC-012, REV2-003)

## Как это работает
- `release.yml` подписывает `SHA256SUMS.txt` ключом Ed25519 из секрета `UPDATE_SIGNING_KEY` и выкладывает подпись в `SHA256SUMS.txt.sig` (hex).
- Открытый ключ вшивается в каждое приложение и сервер при сборке: переменная репозитория `UPDATE_PUBKEY` попадает в `AQUA_UPDATE_PUBKEY`, а оттуда в `aqua_core::release::UPDATE_PUBKEY`.
- Проверка fail-closed: все три механизма обновления (мессенджер, Aquamarine Server, консольный сервер) ставят выпуск, только если `SHA256SUMS.txt` подписан этим ключом.
  - Нет подписи или она неверна: обновление не ставится.
  - Сборка без ключа (сборка разработчика) не ставит обновлений вообще.
- `release.yml` останавливается до сборки, если:
  - не задан секрет;
  - не задана переменная;
  - открытая часть секрета не совпадает с переменной.

## Что сделать владельцу (один раз)
1. Сгенерировать ключ на своём компьютере (не в чате и не в репозитории):
   ```
   openssl genpkey -algorithm ed25519 -out aquamarine-release.pem
   openssl pkey -in aquamarine-release.pem -pubout -outform DER | tail -c 32 | od -An -v -tx1 | tr -d ' \n'; echo
   ```
2. GitHub → Settings → Secrets and variables → Actions:
   - **Secrets** → `UPDATE_SIGNING_KEY` — всё содержимое `aquamarine-release.pem`;
   - **Variables** → `UPDATE_PUBKEY` — 64 hex-символа из второй команды.
3. Хранить `aquamarine-release.pem` офлайн (резервная копия). Без него нельзя выпустить обновление, которое примут уже установленные приложения.

## Переход
- Приложения до этой версии подпись не проверяют и обновятся как раньше.
- Начиная с этой версии ставятся только подписанные выпуски. Поэтому секрет и переменная нужны до первого выпуска с этой версией; иначе `release.yml` остановится, а не выпустит неподписанное.

## Ротация и компрометация
- Новый ключ: новая пара; сначала выпуск, подписанный **старым** ключом, но собранный с новым `UPDATE_PUBKEY`; затем секрет меняется на новый.
- Ключ украден:
  1. Сразу сменить секрет и переменную.
  2. Выпустить версию с новым ключом, подписанную старым ключом, пока он есть у владельца.
  3. Если старого ключа нет, установленные приложения придётся обновить вручную (скачать установщик).
